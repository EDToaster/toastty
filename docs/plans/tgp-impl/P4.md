# P4 — Animation & accessibility

Phase P4 adds terminal-side animation playback and accessibility surfacing to TGP, layered on the scene model (S06), asset/GLB import + acks (S08), the wire/error framing + the `apc_end` outcome back-channel, and the deterministic injectable clock + CPU picking/event emission from the interactivity phase (S12). It delivers: `alt`-text in the scene with bounded validation and CPU-resolved terminal surfacing (S13); glTF clip import + auto-registration with the glTF-index→ClipId mapping returned in the asset `a` ack (S14.1); the opt-in `anim;play/pause/seek/stop` verbs on the deterministic clock with `node=` subtree-root channel resolution (S14.2–14.3); stop/pause/end-of-clip pose + TRS-ownership semantics and the `node_busy`/`camera_busy` conflicts (S14.4–14.5); per-node dirty + animation render-scheduling that never spams `scene_revision` (S14.7 / G9); bind-pose skinning that does NOT advertise `feat=skin` (S14.8); and full RIS/DECSTR/alt-screen lifecycle teardown of playbacks and clips (G10).

Every protocol surface in scope — each verb, header field, error code, cap, feat token, and lifecycle event — gets at least one concrete unit test on the INGRESS (`Parser::advance` → `&self` accessors / `pty_replies`), INTERACTION (synthetic events + explicit clock advance → camera/node TRS or `tgp;e` bytes), or LIFECYCLE (RIS / alt-screen / `node.remove` → teardown via accessors) seam. The `anim` verbs, the clip-id ack, and all anim errors/events route out through the cross-crate `apc_end` outcome back-channel (the foundation-phase change where `toastty-parser::Perform::apc_end` becomes outcome-bearing, returning a parsed-frame result that `Term` turns into queued `tgp;a`/`tgp;x`/`tgp;e` bytes); P4 does NOT re-do that plumbing and the relevant tasks (P4-T4, P4-T7, P4-T9) depend on it explicitly as `APC-END-BACKCHANNEL`.

**Cross-phase dependency aliases** (all reference EARLIER phases P1–P3): `SCENE-MODEL`, `ASSET-ADD`, `ACK-FRAME`, `TGP-FOUNDATION`, `ERROR-FRAME`, `APC-END-BACKCHANNEL` (P1 Foundation); `CLOCK`, `PICK`, `EVENT-EMIT`, `EXPLORE` (P2 Differentiators); `CAPS-REPLY` (P1 handshake/`tgp;r`); `LIFECYCLE` → **P2-T38** (RIS/DECSTR teardown machinery) + **P2-T15** (alt-screen affinity / screen-buffer binding) — the established lifecycle/affinity machinery P4-T15 wires animation state into (G10). Where the interactivity phase already landed the shared clock, P4-T0 re-exports it rather than duplicating.

**Design-reconciliation items surfaced by this phase** (resolved minimally here; flagged for the design owners): (1) S12.5's closed `ev=` enum does NOT contain `anim_end`, but S14.4 emits it — P4-T9a extends the EVENT-EMIT closed `ev=` vocabulary with a node-scoped `anim_end` token (fields `tok=`/`vp=`/`node=`/`clip=`/`reason=`), versioned under `v=`. (2) S13.1 says the scene "may carry an `alt` caption" but defines NO wire op to set it — scene-level `alt` is therefore **out of scope for v1** in P4. (3) S13.1 also says "each viewport may carry an `alt` caption", and S13.2 makes the viewport `alt` the headline cell-fallback caption that AT readers announce in the text flow — but the authoritative `Viewport` struct in S10.1 has NO `alt` field and the S10 `tgp;vp` op schema defines no `alt=` field. P4-T1 therefore carries an explicit **design-reconciliation item that EXTENDS S10.1**: add `alt: Option<String>` to the `Viewport` struct and define a concrete `alt` key on the `tgp;vp` create/update op payload (CBOR `alt` text-string key, mirroring the `node.upsert` `alt` key), governed by the SAME bounded `validate_alt` hardening (UTF-8, ≤64 bytes, no C0/DEL/C1/ESC) and the SAME `bad_param` whole-frame reject as node `alt`. This wire definition is added by P4-T1; viewport `alt` is in scope only because P4-T1 lands that S10 extension, and the a11y surfacing in P4-T2 (`viewport_accessible_name`, the cell-fallback caption) depends on it.

**Concrete-clip-id convention (G6 — every anim test feeds real wire bytes):** clip ids are numeric `u32` handles read from the asset `a` ack (S14.1), never the literal letter `C`. To keep every anim test concrete, the phase pins a fixture rule: for a single-animation GLB fixture, glTF-animation-index 0 maps to **`ClipId 0`** in the creating token's namespace, so a test that `asset.add`s a one-clip GLB writes `clip=0` in its anim frames. A test that needs to be explicit drains the `a` ack and binds its clip id from the `clip0=` mapping field, then writes that literal `u32` in the frame. Every P4-T6/T7/T9/T10/T11/T12/T13/T15 anim test below states the numeric `clip=` value it feeds (e.g. `clip=0`), never the placeholder `C`.

**Design-reconciliation item — the `clipN=` ack-mapping field spelling (round-3 review P4-R3-6):** S14.1 specifies that the commit `a` ack "returns the glTF-animation-index → `ClipId` mapping," and S08.5 fixes that clip ids are `u32` handles, but neither slice pins a concrete *wire spelling* for that mapping field. P4-T4 therefore LANDS the concrete spelling **`clipN=<u32>`** — one key per glTF animation index N (`clip0=<id0>`, `clip1=<id1>`, …) — and this spelling is **flagged for the design owners** at the same standard as the other two flagged inventions in this phase (the viewport `alt` = S10.1 extension in P4-T1; the `ev=anim_end`/`reason=` = S12.5 extension in P4-T9a). The P4-T4 test's literal `clip0=`/`clip1=` field names are authoritative for this phase, not incidental.

## P4-T1 — Add `alt` to the scene model (nodes, viewports) with bounded validation

**Title:** Add `alt` to the scene model (nodes, viewports) with bounded validation

**Deliverable:** `toastty-graphics/src/tgp/scene.rs`: add `alt: Option<String>` to `Node` (already in the S06.1 struct). Add `validate_alt(&[u8]) -> Result<String, TgpError>` enforcing: valid UTF-8 (non-UTF-8 → `bad_param`); ≤ `max_id_bytes` (64 bytes, counted in **bytes** not chars, per S13.1 / S07.1); and rejection of any C0 control byte (`0x00`–`0x1F`), DEL (`0x7F`), C1 range (`0x80`–`0x9F`), or ESC (`0x1B`) — the exact id-hardening set of S08.4 that S13.1 says `alt` inherits because these strings can re-enter the host input path via AT tooling. Wire `alt` into the `node.upsert` sparse merge (key absent = preserve; CBOR null = clear to `None`; value = set — S06.1 table). Add accessor `Node::alt() -> Option<&str>`. **Alt-cap design decision (round-2 review P4-R2-4):** S13.1 says `alt` is "bounded like every other string field (UTF-8, ≤ 64 bytes...)" and S07.1 advertises `max_id_bytes=64` but no separate `max_alt_bytes`; this task pins the decision that the `alt` cap IS the advertised `max_id_bytes` (no new cap token), and the over-cap tests below read the bound from the advertised `max_id_bytes` (NOT a hard-coded literal 64) so the G7 advertised==enforced invariant holds for `alt` and the tests do not silently drift if a future caps change splits alt off. (A future design may name `max_alt_bytes`; until then `alt` shares `max_id_bytes` by this explicit decision — flagged for the design owners.)

**S10 viewport-`alt` wire extension (design-reconciliation item 3 above):** the authoritative `Viewport` struct in S10.1 has NO `alt` field and the S10 `tgp;vp` op defines no `alt=` key — but S13.1/S13.2 make viewport `alt` the headline cell-fallback caption. Add accessor `Viewport::alt() -> Option<&str>`. **Scene-level `alt` is out of scope** (no wire op exists, S13.1 reconciliation item 2 above).
