## Issues

### I-1 — DEDUP duty names `encode_ack`, P5-T25 reuses `emit_ack` (naming drift with P1-T17)
- **id:** P5-T25 deliverable / DEDUP note (lines 484, 486, 492; cleanup-log line 581)
- **severity:** low
- **problem:** The dedup duty (and the cleanup-log heading at line 581) name the P1-T17 ack primitive `encode_ack`, but the P5-T25 body consistently reuses `emit_ack` (the analogous P5-T1 reuse correctly names `encode_error`, matching its duty). P5.md is internally consistent (always `emit_ack`), so this is not a self-contradiction inside P5; it is a cross-task naming-alignment risk: if P1-T17 actually ships the formatter under one of these names and the queue-emit wrapper under the other, an implementer reading only the dedup heading could look for the wrong symbol. The reuse intent is unambiguous and correct (do not redefine the ack primitive), so this does not break the DEDUP duty.
- **fix:** Pick one spelling and use it in both the duty heading and the body. Recommend matching the P5-T1 pattern: name the encoder `encode_ack` (parallel to `encode_error`) and, if a separate term-side queue wrapper exists, call it `emit_ack` and say so once. Cross-check against P1-T17's actual symbol names so P5's depends-on cites the real exported name.

### I-2 — Cleanup-log records P5-R-03 spelling that is superseded but left inline without an at-the-table pointer
- **id:** P5.md round-1 log P5-R-03 (line 527) vs P5-6 (line 548)
- **severity:** low
- **problem:** P5-R-03 records the now-superseded shared `detail=max_viewport_px` spelling; P5-6 supersedes it with the axis-specific `max_viewport_px_w`/`_h` and notes the round-1 entry "is left as a historical record." The actual T16 deliverable and tests (lines 311–312) correctly use the axis-specific names, so there is no live contradiction in the normative text. The only residue is that the two log entries disagree by design, which is fine, but a reader skimming only the round-1 log could briefly mis-read the spelling.
- **fix:** None required for correctness (the normative T16 text and tests are unambiguous and already cited as superseding). Optionally add a one-word "(SUPERSEDED by P5-6)" tag at the head of P5-R-03 for skim-safety. Non-blocking.
