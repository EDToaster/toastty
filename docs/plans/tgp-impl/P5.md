# P5 — Hardening & lifecycle

This phase closes the protocol against untrusted input and ties off every lifecycle event. It enforces every advertised **allocation/framing/structural cap** *before* allocation with the recurring drain-then-error shape, wires the closed versioned structured-error taxonomy (G3) end-to-end (gated on handshake per G5, tagged/routed per G1/G4, with the **reachable/reserved partition fixed by G12.2/G12.3**), isolates objects per-token via **private per-token id maps as the confused-deputy fix (G11, authoritative — supersedes G1's ownership-tagged single-global-namespace `denied`-on-cross-token model)**, stands up the single fuzz oracle at the `Parser::advance(&mut Term)` ingress seam (G6/G8), and implements G10 lifecycle: RIS teardown, DECSTR no-op, alt-screen affinity, CSI 2J/ED inline-placeholder erase, scrollback eviction, GPU device-loss force-reupload, and PTY-EOF mid-binary cleanup. For sections 7/10/8 it covers only their caps-enforcement, framing-robustness, and lifecycle surfaces (core surfaces shipped in P1/P2).

**Addendum binding (G11/G12, authoritative — supersedes the base spine and the s07/s08/s10/s15 slices on conflict).** Three taxonomy rulings reshape this phase's error emissions: (1) **G11** — cross-token addressing is *unrepresentable* under the private per-token map, so `denied` is **RESERVED** (no reachable ingress trigger; carried only by the closed-set round-trip); a cross-token id "collision" is **coexistence**, a cross-token handle ref is **`bad_ref`** (no existence oracle), a cross-token viewport `camera`/`root` is **late-bind default**, and a no-handshake token-requiring frame is **`bad_token`** (a well-formed tokenless `tgp;p` is a silent drop). (2) **G12.1** — an over-`max_msg_mb` breach is canonically **`cap_exceeded;detail=max_msg`**; `msg_too_large` is **RESERVED**. (3) **G12.2/G12.3** — the two reserved codes are `msg_too_large` and `denied` (**24 reachable, 2 reserved**); `unknown_op` is **REACHABLE** via the P4 closed-anim-verb locus (G12.3 row 8) — *not* reserved, just not emitted by any P5 ingress path; **G12.4** — `instanced_node_tint` is **`kind_conflict;detail=instanced_node_tint`** (the `bad_param` synonym is struck). Every P5 error-emission test below conforms to this partition.

**DEDUP framing (binding on P5-T1 / P5-T25).** Two P5 deliverables are reframed as **extensions** of P1 tasks rather than re-implementations: **P5-T1 CONSUMES P1-T16** (reuses the `TgpErrorCode` enum + `wire_code` + `encode_error`; adds only the `ErrorCorr` correlator routing + the `emit_error` formatter + the handshake/focus `should_emit` gating P5 introduces — it does **not** redefine the enum or re-create `error.rs`); **P5-T25 REUSES P1-T17's `encode_ack`** (and its ack sites) and adds **only** the new `max_backchannel_bytes` enforcement on the shared reply queue. See each task's DEDUP note.

**Cap-ownership scope (G7 "advertised == enforced").** Of the closed advertised cap set (s07.1 / s15.2), P5 owns every *allocation, framing, structural, and sizing* cap — the per-asset/per-buffer, per-message, per-session reassembly/VRAM/node/depth/viewport/light/pending caps, the inline/pixel sizing caps, `max_id_bytes`, and `max_backchannel_bytes` (each gets a P5 reject test below, with its exact `detail=` field name). Three advertised members are **enforced in their owning phase, OOS for P5's caps tasks** because they clamp/throttle a *behavioral* surface rather than gate an allocation: **`anim_speed_max`** is enforced by P4 anim playback (clamp/reject of `anim;play;speed>cap`), **`camera_report_hz`** is enforced by P2/P4 explore as the camera-report throttle (driven off the G6 injectable clock), and the negotiation-hint members **`msaa`** and **`click_deadzone_px`** are render/interaction options owned by P3/P2 with no reject path. Their enforcement/clamp tests live in the owning phase; P5's "enforces every advertised cap before allocation" claim is scoped to the allocation/framing/structural/sizing caps it owns and does **not** silently absorb these four. This keeps G7's advertised-set == enforced-set whole across the plan without P5 double-owning behavioral clamps.

The cross-crate change called out throughout: the `toastty-parser` APC back-channel (`apc_end(&mut self) -> ApcEnd`, where `ApcEnd = Done | BinaryFollows { len, enc }`) and its drain/abort states are co-owned by parser and term; tasks that touch binary-frame draining, EOF cleanup, or inactivity abort name it explicitly.

## P5-T3

**Title:** Per-token namespace isolation — PRIVATE per-token id maps (`denied` RESERVED)

**Deliverable (rewritten per G11).** In `toastty-graphics` scene tables, implement the ratified **private per-token id map** model (G11): each handshaked token `T` owns a *physically disjoint* `T → (id → object)` map covering node/asset/material/clip/viewport ids. A reference resolves as `(bearing_token, id)`, **never** as `id` alone, and a token's lookup path touches **only its own storage** — no global id table, no shared bucket a cross-token key could land in, no cross-token lookup primitive anywhere (G11(b′), the no-side-channel rule: a single global `(id→object)` table is **non-conforming**). Add `fn resolve_owned(&self, tok: &TokenId, id: &Id) -> Option<&Obj>` that indexes only `tok`'s sub-map and returns `None` on a miss — it is the ordinary in-namespace resolver, **not** a cross-token gate.

**`denied` is RESERVED — no reachable trigger (G11(a), G12.2).** Because a frame can only ever name ids inside its own map, cross-token addressing is **unrepresentable by construction**; there is no ingress event that produces "you named someone else's object." `denied` therefore stays a member of the closed G3 enum (carried by P5-T1's `error_code_wire_strings_closed_set` round-trip) but has **no reachable ingress emitter** in v1 — exactly the reserved-by-precedent treatment `msg_too_large` gets (the other genuinely RESERVED code; `unknown_op`, by contrast, is REACHABLE via the P4 closed-anim-verb locus, G12.3 row 8). The confused-deputy attack is defeated by the private map (B2 *cannot* address A1's `"car"`); it is not backstopped by a runtime `denied` check, which would be dead code. The only observable cross-token outcomes are: **coexistence** (each token's own id), **`bad_ref`** (a handle/patch ref absent from the bearing token's map — no existence oracle, G11(b)), **late-bind default** (viewport `camera`/`root` absent from the map, G11(c)/G2), or **`bad_token`** (no valid handshake, G11(d)/P5-T4).

**Resolver routing (resolves review I-1/I-2/I-3).** Narrow the resolver behaviors per kind:
- **String node-id `upsert`/`remove`** under token `T` always index `(T,id)`: a "collision" with another token's `(A,id)` is **not representable** — the lookup simply hits or misses `T`'s own entry, so `B2.upsert("car")` creates B2's own `"car"` (coexists with `A1`'s), never `denied` (resolves I-6).
- **Handle refs** (`mesh`/`asset`/`material`/`tex`, all `u32`) resolve through the ordinary txn-final resolver against `T`'s committed map; a miss → `code=bad_ref;detail=<kind>:<id>`, **byte-for-byte indistinguishable** from "never created anywhere" (no existence oracle, G11(b)) — never `denied` (resolves I-2).
- **Viewport `camera`/`root`** are **late-bound** (not patch refs, G2/G11(c)): a miss in `T`'s map → render with the implicit auto-framing default camera / whole-scene root, never reject, never `denied` (resolves I-1; the create-before-camera and remove-fallback tests live in P5-T16).

**Note:** numeric handle refs resolve purely within the requester's namespace and a miss is `bad_ref`; string-id `upsert`/`remove`/`parent` index only the requester's own map (a miss creates, for `upsert`, or no-ops, for `remove`). The terminal MUST NOT distinguish "exists under another token" from "never existed" for any resolver (G11(b)).

**Design refs:** §15.2 (addressing isolation, superseded by G11), §8.4 (denied prose superseded by G11), §7.1 (per-app token); **G11 (private per-token map, authoritative), G12.2 (denied RESERVED), G2 (late-bind).**

**Depends on:** P1 scene tables, P1 patch apply/staging, P5-T1, P5-T2.

## P5-T6

**Title:** `max_msg_mb` enforced at text-header parse + drain-then-error (`enc=bin`)

**Deliverable:** **Cross-crate apc_end change.** In `toastty-parser`, the APC-end hook returns `ApcEnd::BinaryFollows { len, enc }`; in `toastty-term`'s header parse, validate `len` against `max_msg_mb` **before** the pre-scanner enters consume-N. The drain-then-error shape applies to **`enc=bin` only** — only `enc=bin` engages the raw-byte-count binary-read state (§8.2/§8.3). On over-cap for `enc=bin` the term still signals `BinaryFollows` so the pre-scanner drains exactly `len` bytes (escape-scan disabled), discards them (no buffering), returns to Ground, and term emits **`code=cap_exceeded;detail=max_msg`** citing the header `txn` (no `op=`, pre-decode). The drain path lives in the parser's binary-read state with a `drain_only: bool` so no accumulation buffer is allocated when over-cap. Add `Term::pending_bytes() -> usize` accessor (returns 0 after a drain completes).

**Canonical code is `cap_exceeded;detail=max_msg` (G12.1, supersedes `msg_too_large`).** The base spine and s15.2/s15.3 historically named a separate `msg_too_large` code for this breach; G12.1 funnels **both** over-`max_msg_mb` loci (the `enc=bin` drain path here and the b64/already-buffered decode-size reject below) through the single `cap_exceeded;detail=max_msg`, and **`msg_too_large` is RESERVED** (closed-set round-trip only, no reachable ingress trigger — P5-T1 `reserved_codes_round_trip_only`). Read the s15.2 message-size locus (`s15.md:54`) and the s15.3 example (`s15.md:112`) as emitting `cap_exceeded;detail=max_msg` — the drain-then-error/correlation shape is unchanged, only the code. `detail=` is advisory/non-load-bearing (G3); tests branch on `code=cap_exceeded` and MAY additionally check `detail=max_msg` as documentation.

**b64 over-cap (no drain).** `enc=b64` **never** enters binary-read / consume-N: it stays inside the ST-terminated APC. `max_msg_mb` is the **decoded** size and applies identically to both encodings; for b64 the in-APC encoded length is bounded at `ceil(max_msg_mb×4/3)` (§7.1/§15.2), so an over-cap b64 frame is detected at header parse (encoded char count over the b64 bound) or at decode, **rejected without any drain loop and without entering binary-read state** (the ST still delimits the APC) with the same `code=cap_exceeded;detail=max_msg` (G12.1, shared decoded-size contract). `pending_bytes` is an `enc=bin`-only accessor and is never nonzero for a b64 frame.

**Design refs:** §15.2 (message size; the `msg_too_large` spelling there is superseded by G12.1), §8.2 (apc_end back-channel, binary-read is bin-only), §8.3 (b64 stays in-APC, decoded-size cap shared), §7.1 (decoded `max_msg_mb`, b64 bound `ceil(max*4/3)`), §8.7 (`cap_exceeded;detail=max_msg` on overflow, drain-then-discard); **G12.1 (canonical `cap_exceeded;detail=max_msg`), G3, G4.**

**Depends on:** P1 binary framing + apc_end signal, P5-T1, P5-T2.

**Tests:**

## P5-T25

**Title:** `max_backchannel_bytes` enforcement on the ack/error/event queue — EXTENDS P1-T17

**DEDUP note (binding).** This task **REUSES P1-T17's `encode_ack`** (the `tgp;a;tok=…;[txn=|vp=|asset=]…` formatter + its txn-commit/`enc=bin`-probe ack semantics + correlator routing). Do **not** re-define `encode_ack`, its signature, or its ack-emission sites here — those ship in P1-T17. **P5-T25 adds ONLY the new `max_backchannel_bytes` enforcement** in the shared queueing path that `emit_error`/`encode_ack`/`emit_event` all funnel through, plus the `Term::backchannel_pending(tok)` accessor. The ack-correlation behavior is exercised by P1-T17; the few ack tests retained below are regression guards confirming the backchannel cap does not break the P1-T17 ack path (and pinning the v1 no-`vp`-ack site so the cap path sees the right frame set).

**Reused from P1-T17 (not re-specified):** `encode_ack(tok, corr)` → `ESC _ tgp;a;tok=<T>;[txn=|vp=|asset=]… ESC \`; acks available to **any handshaked token** (not gated on `sub`, G4); route through `should_emit` (P5-T2); cite the acked frame's correlator (`txn=` patch-commit §8.6, `asset=` `more=0` chunk-commit §8.7, `txn=` `enc=bin` probe §7.1); v1 does **not** ack `vp` frames (the `encode_ack` signature accepts a `vp=` correlator for G4 completeness but has no v1 positive `vp` ack site); a binary frame that fails to decode draws `parse_error`, never an ack.

**New in P5-T25 — `max_backchannel_bytes` enforcement (G7 advertised=enforced).** All three terminal→app reply types (`tgp;x`/`tgp;a`/`tgp;e`) share the single PTY writeback FIFO, so the advertised per-session `max_backchannel_bytes` cap (s07.1, default **4096**) bounds the queued-but-undrained reply volume per token. Enforce it in the shared queueing path used by `emit_error`/`encode_ack`/`emit_event` (the P1-T16/T17 emit primitives consumed by P5-T1/T2 + §12 events): before queueing a frame, if the token's currently-queued (not-yet-flushed-to-PTY) reply bytes plus the new frame would exceed `max_backchannel_bytes`, **drop the new frame rather than queue it** (a flood of events/errors cannot itself wedge the PTY writeback). The cap is per-token and measured against bytes still pending in `pty_replies` for that token; bytes drained to the PTY no longer count. Add `Term::backchannel_pending(tok) -> usize`. (Dropped acks/errors are dropped silently — the app already lost the channel to backpressure; the cap is a safety bound, not a delivery guarantee.)

**Design refs:** §8.6 (acks — P1-T17), §7.1 (enc=bin probe — P1-T17; `max_backchannel_bytes` — this task), §8.3; G4, G5, G7.

**Depends on:** P1-T17 (`encode_ack` + ack sites, **reused not redefined**), P1 patch commit, P5-T1, P5-T2.

**Tests:**
- `ack_on_commit` / ingress / handshaked `A1` commits a valid `tgp;p;txn=90` / assert `tgp;a;tok=A1;txn=90` queued.
- `ack_not_gated_on_sub` / ingress / handshaked `A1` with **no** subscription commits a txn / assert ack still queued (acks need only handshake).
- `ack_asset_correlator` / ingress / handshaked `A1` completes a chunked upload of asset `5` (`more=0` final frame commits) / assert `tgp;a;tok=A1;asset=5` queued (asset correlator on the chunk-commit ack, G4), and no `txn=`.
- `vp_commit_no_ack` / ingress / handshaked `A1` creates a valid pinned viewport via `tgp;vp` / assert **no** `tgp;a` is queued for it (v1 does not ack `vp` frames; the viewport's existence is observable via `viewport_count`/`viewport_pixel_rect`). Confirms the v1 ack-emission-site closure above.
- `enc_bin_probe_ack` / ingress / handshaked `A1` sends a minimal no-op `enc=bin;txn=91` patch (the probe) / assert `tgp;a;tok=A1;txn=91` queued.
- `failed_decode_no_ack` / ingress / `enc=bin` frame that fails to decode / assert `code=parse_error` queued and **no** `tgp;a` for that txn.
- `ack_unhandshaked_silent` / ingress / tokenless writer's frame that would otherwise commit / assert no `tgp;a` queued (G5).
- `backchannel_over_cap_drops_frame` / ingress / handshaked `A1`; without draining `pty_replies`, drive enough error/ack emissions that the cumulative queued bytes for `A1` reach `max_backchannel_bytes`, then trigger one more `emit_error` / assert the extra frame is **not** queued (`backchannel_pending("A1")` does not exceed `max_backchannel_bytes`) and no panic; after draining `pty_replies`, a subsequent `emit_error` queues normally (cap measured against still-pending bytes).
