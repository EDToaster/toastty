# P1 — Foundation

This phase stands up the entire CPU-side spine of TGP end to end: the binary/control framer (including the cross-crate `apc_end -> ApcEnd::BinaryFollows{len,enc,trl}` back-channel that lets the dumb pre-scanner enter byte-counted binary-read mode, plus the opt-in `trl=1` integrity trailer), CBOR patch decode, the always-answered capability handshake (`tgp;r` before DA1, per-token namespace), the retained per-token scene model with `u64` revisions and per-node/per-viewport dirty flags, inline GLB assets with hardened bounds-checked accessors, the PINNED default material, the injectable deterministic clock, and a single viewport rendered at compositing parity. Every protocol surface introduced here — each op/verb, header field, error code, capability, and lifecycle event in scope — gets at least one GPU-free unit test at the ingress or lifecycle seam, asserting CPU-side state via `&self` accessors (`Term::tgp_scene()`, pixel rects, decoded buffers, revisions/dirty flags) or queued `pty_replies` bytes.

**P1 scope clarifications (round-1 review resolutions).** The following are explicitly **in P1** because they are pure-CPU protocol surfaces the testing contract requires: (a) `material.add` op decode + commit (default-material-only fields applied; PBR fields parsed-but-inert) — bumps `asset_revision`; (b) `node.instances` **decode + hardened layout/cap/NaN validation** storing the decoded `InstanceBuffer` (GPU upload + instanced draw defer to P2) — bumps `scene_revision` + `instance_dirty`, never `asset_revision`; (c) **node-id charset/length hardening** (≤64 bytes, no control/ESC → `bad_param;detail=charset|too_long`, §8.4/§15.5); (d) the **`trl=1` integrity trailer** parse + verify (advertised `bintrailer` feat is honored); (e) the three over-length binary-frame branches (ok / over-`max_msg_mb` drain-then-`cap_exceeded;detail=max_msg` / over-`BIN_HARD_CEIL` no-drain-`cap_exceeded;detail=unrecoverable`) — per **G12.1** the per-message decoded-size breach is `cap_exceeded;detail=max_msg` on BOTH the bin-drain and the decode-reject loci (`msg_too_large` is RESERVED, never emitted in P1); (f) an **empty-ops patch** is a valid commit that acks (bin-probe path). Per the **G11/G12 addendum (authoritative)**: a node-level tint on an `Instanced` node encodes as **`code=kind_conflict;detail=instanced_node_tint`** — **G12.4** rules this the single canonical code (a kind-invariant violation) and **strikes** the base-spine `instanced_node_tint→bad_param` synonym, so the addendum supersedes round-1's prior `bad_param` resolution (I9 is re-decided). `bad_param` remains reachable only on its own triggers (node-id charset/length, out-of-range op fields). Per **§7.3/G12.2** every unknown `do:` patch op string is **skipped** (not `unknown_op`), so `unknown_op` is in the closed enum and is **NOT P1-reachable** — but it is globally **REACHABLE** via the **P4 closed-anim-verb locus** (a verb outside the closed `anim` set {play,pause,seek,stop}, s14.3, is a malformed control frame that draws `unknown_op`, G12.3 row 8); it is therefore **NOT** a member of the reserved set, only *reserved for patch ops*. Per **G11(a)/G12.2** the two genuinely **RESERVED** codes (no reachable ingress trigger anywhere) are `denied` and `msg_too_large`: cross-token id collisions COEXIST as distinct `{tok,id}` entries under the private per-token id map (never `denied`), and the over-msg-cap breach funnels through `cap_exceeded;detail=max_msg` (never `msg_too_large`). Per **§10.2/§10.3** an over-cap viewport is **rejected** (`cap_exceeded`), never silently clamped (the on-screen-intersection clamp is a separate, legitimate clamp).

**Isolation model (G11, authoritative).** P1 implements the ratified **private per-token id map**: each handshaked token owns a `T → (id → object)` map that no other token can index, so cross-token addressing is **unrepresentable by construction** (there is no shared id table, no cross-token lookup primitive). Two tokens that each create `"cam"` (or asset `7`, or viewport `9`) hold **two distinct, coexisting entries** `{A,"cam"}` and `{B,"cam"}` — this is **not** a collision and is **never** `denied`. Per **G11(b′)** the per-token maps MUST be **physically disjoint allocations** (token T's lookups never index/hash-into/contend any structure holding another token's entries) so the no-existence-oracle guarantee survives at the implementation level. `denied` is therefore **RESERVED** (closed-enum member, no reachable ingress trigger). Threat-model honesty (G11 scope): the token is a bearer credential with no unguessability requirement, echoed in cleartext; the private map defeats *accidental* collisions and *unguessing* adversaries but a stream-reading adversary who learns a token can write same-token frames that resolve and mutate the victim's objects without ever drawing `denied` — token confidentiality is load-bearing for isolation.

**RIS teardown (G10, in P1 — R3-2).** Because P1 is the phase that *creates* the per-token scene/session/reasm tables (T4/T7/T10/T14), it is also the canonical owner of their teardown hook: **RIS (`ESC c`) tears down the entire TGP scene across all tokens** (assets, materials, nodes, viewports, in-flight reassembly buffers) and invalidates all session tokens — the guaranteed VRAM-recovery path (§10.7 line 79, G10). **DECSTR (`ESC [ ! p`) leaves the TGP scene intact.** This lands in T4 (folded) so the create-without-teardown asymmetry is never shipped untested.

Out of scope and deferred to later phases: multi-viewport/reflow/instancing **render**/picking/events/explore/subscriptions (P2; `node.instance_set` re-tint, `sub` behavior); PBR pipeline/lights/MSAA/tone-map (P3); animation/accessibility (P4; `anim` behavior); and full lifecycle hardening beyond RIS/DECSTR — alt-screen/scrollback-eviction/`2J`/device-loss/PTY-EOF (P5). `sub`/`anim` control frames are **parsed and treated as safe no-ops** in P1 (recognized FrameType, never crash, no scene mutation); only default material + compositing parity of §11 lands here.

## P1-T1 — APC back-channel: `apc_end` returns a typed binary-follow signal (cross-crate change)

**Title:** Cross-crate `apc_end -> ApcEnd` parser/term back-channel (`Done | BinaryFollows{len,enc,trl}`).

**Deliverable:** Change the dumb APC pre-scanner so the Perform layer can tell it to enter byte-counted binary-read mode. In `crates/toastty-parser/src/perform.rs`: change `Perform::apc_end(&mut self)` to `fn apc_end(&mut self) -> ApcEnd`, and add the typed return `enum ApcEnd { Done, BinaryFollows { len: u64, enc: BinEnc, trl: bool } }` with `enum BinEnc { Bin }` (today it returns unit — this is the required signature change). The `trl: bool` carries whether the header set `trl=1` so the pre-scanner knows to read the 8-byte integrity trailer (§8.2) AFTER the `len` raw bytes — the trailer is NOT counted in `len` (P1-T2 handles the trailer bytes; the back-channel only signals its presence). In `crates/toastty-parser/src/parser.rs` (the `apc_end` call site, ~line 190) the parser inspects the returned `ApcEnd`: on `Done` it returns to Ground as today; on `BinaryFollows{len,enc,trl}` it transitions Ground → a new `BinaryRead { remaining: u64, enc: BinEnc, trl: bool }` parser state with escape-scanning disabled. Update the `BufferingApcHandler` forwarder and `VteAdapter` bridge to propagate the new return. The pre-scanner stays dumb: it holds NO `tgp`/CBOR/`len` knowledge; the Term/Perform impl (P1-T4) is what parses the header and decides the return value. Add a default `Perform::apc_end` body returning `ApcEnd::Done` so existing handlers (kitty/sixel/rgp) compile unchanged. **`BinEnc` vs `Enc` (J3):** `enum BinEnc { Bin }` lives in `toastty-parser` and is intentionally a **one-variant subset** — only `enc=bin` ever triggers the binary-read state, so the dumb pre-scanner only needs to know "this is a raw-byte frame." The full header enum `enum Enc { B64, Bin }` lives in `toastty-graphics` (P1-T3); the Term maps `Enc::Bin → BinEnc::Bin` when it returns `BinaryFollows`. `Enc::B64` never reaches the back-channel (b64 stays inside the APC, returns `Done`), which is why `BinEnc` has no `B64` variant.

**Design refs:** §8.2 (parser back-channel, normative); §5 (single ingress path). G-invariants: G6 (ingress seam), G8 (no RGP bridge — change is additive to the shared pre-scanner, not a fork). **Doc-consistency note (R3-3):** the s08 §8.2 inline code block spells the enum `BinaryFollows{len,enc}` (no `trl`), but that block predates the same section's "Integrity trailer (opt-in)" paragraph + the advertised `bintrailer` feat (§7.1) + I4, which JOINTLY require the back-channel to carry trailer presence (a Term cannot otherwise tell the dumb pre-scanner to read the 8 trailer bytes without re-parsing). The authoritative shape is therefore `BinaryFollows{len,enc,trl}` (the trailer paragraph + `bintrailer` feat win over the stale code block); `ApcEnd`/`BinEnc` are internal Rust API, not wire spellings, so G8/G1 are untouched. A doc-fix against s08 to add `trl` to the inline enum is filed separately.

**Depends on:** none.

**Tests:**

## P1-T2 — Binary-read state machine: cross-`advance()` byte counting, optional-ST tolerance, hard ceiling

**Title:** Cap-bounded `BinaryRead` state that survives split reads and resyncs against length lies.

**Deliverable:** Implement the `BinaryRead` parser state in `crates/toastty-parser/src/parser.rs` (state added in P1-T1). Carry `remaining: u64`, the `enc`, the `trl` flag, the captured header `txn` (for truncation diagnostics), and a cap-bounded accumulation buffer. Each `advance()` appends `min(remaining, available)` bytes and decrements `remaining`; on `remaining == 0` the buffer is handed to the Term decoder hook (P1-T4 `Term::tgp_feed_binary`) and the parser returns to Ground. If the input slice empties first, the state is retained for the next call. After the Nth byte, tolerate exactly **one** trailing ST token (`ESC \`, `BEL`, or `0x9C`) consumed as a no-op sync marker; a second consecutive ST is ordinary input.

**Three over-length branches (the framer must distinguish all three; this resolves I11):**
1. `len > BIN_HARD_CEIL` (compile-time constant ≥ `max_reasm_mb`): return to Ground at the header boundary WITHOUT draining; surface a synthetic over-ceiling signal via `Term::tgp_feed_binary_overceil` (drives `cap_exceeded;detail=unrecoverable`). This is the no-drain branch.
2. `Caps::max_msg_bytes() < len ≤ BIN_HARD_CEIL` (the common over-cap case; `max_msg_bytes() = max_msg_mb * 1024 * 1024 = 67_108_864`, pinned in P1-T6 per J3): enter a **drain-only** consume-N mode — consume exactly `len` raw bytes WITHOUT buffering them (no allocation grows), return to Ground after the Nth byte, then surface an over-msg-cap signal via `Term::tgp_feed_binary_overmsg(txn)` (drives **`cap_exceeded;detail=max_msg`** citing the header `txn` — per **G12.1**: the per-message decoded-size breach is canonically `cap_exceeded;detail=max_msg`, honoring §8.7's literal text; the base-spine `msg_too_large` is RESERVED and never emitted). This keeps the stream synced so the next `tgp;` header re-parses. The over-cap check happens at **header-parse time, before entering consume-N** (§15.2 "before entering consume-N mode").
3. `len ≤ Caps::max_msg_bytes()`: ordinary buffered read into the cap-bounded accumulation buffer.

The accumulation buffer never exceeds the per-frame cap regardless of split.

**Integrity trailer (`trl=1`, §8.2, opt-in `bintrailer`):** when the `BinaryRead` state carries `trl==true`, after the `len` payload bytes the parser reads 8 more bytes (NOT counted in `len`) and hands them to `Term::tgp_feed_binary` alongside the payload as the trailer; the Term verifies `TGPB` magic (`0x54 0x47 0x50 0x42`) + LE-u32 echo of `len`. A mismatched or absent trailer → `parse_error;detail=trailer_corrupt`, scene unchanged, parser back in Ground. The optional-ST tolerance applies after the trailer when `trl=1` (else after the payload). The 8 trailer bytes participate in cross-`advance()` straddling like the payload.

**Design refs:** §8.2 (cross-read lifecycle; optional-ST tolerance bounded to one token; integrity trailer `trl=1`, 8 bytes `TGPB`+LE-len echo not counted in `len`, mismatch→`parse_error;detail=trailer_corrupt`); §8.7 + §15.2 (`BIN_HARD_CEIL` no-drain→`cap_exceeded;detail=unrecoverable`; over-`max_msg_mb` drain-then-`cap_exceeded;detail=max_msg` per **G12.1**, which supersedes the §15.2 `msg_too_large` locus; over-cap check before consume-N). G-invariants: G6 (ingress seam), G2 (resync vs hostile sender), **G12.1** (over-msg-cap canonical code).

**Depends on:** P1-T1.
