# P2 — Differentiators

This phase builds the features that make TGP more than "GLB in a cell": multiple viewports anchored to authoritative inline placeholder cells (per F3) plus pinned regions, each with its own offscreen color+depth target and depth-aware compositing against the constant-depth text plane; terminal-driven reflow that follows the cells; the GPU instancing **render path** + the single-instance re-tint write op (the canonical column-major mat4 f32 LE + RGBA8 **decode/validation is owned by P1-T12**, which P2 **reuses** — P2 does not re-implement a second decoder; see the per-task DEDUP notes on P2-T16/T17); and the full interactivity spine — CPU-resolvable picking (G6), `tgp;e` event reports, per-viewport `sub` subscriptions, the explore camera controller, and F4 input routing that captures the viewport cell rect and suppresses SGR there. All geometry (world matrices, pixel rects, instance decode, pick resolution) stays CPU-side and queryable so every surface is GPU-free testable across the ingress, interaction, and lifecycle seams. It depends on the P1 foundation (framer/CBOR decode, caps/handshake, scene model, **P1-T12 instance decode/validation**, one viewport, the deterministic clock, and the `Term::tgp_scene()` / `pty_replies` seams) and never on any later phase.

> Cross-phase note: P1 establishes `tgp/*` greenfield trees in `toastty-graphics` (scene/decoder), `toastty-render` (one offscreen-less pass), and `toastty-term` (`Term::tgp_scene()` `&self` accessor + `queue_reply → pty_replies`). This phase **explicitly changes the cross-crate `apc_end` back-channel** so the parser returns decoded TGP frames to `Term` and so `Term` can surface decoded viewport/instance/pick state to tests; that change is called out where it occurs (see P2-T1).

> Feature-gating note (G7): the `feat=` token set and its implication rules (`instance⇒graph`, `pick⇒event`, `explore⇒event`) are **negotiated at handshake in P1**, and the closed-enum `unsupported` reply for a feature a terminal does not advertise is owned and tested by P1's handshake tasks. P2's instancing (P2-T16/T19), pick (P2-T20), and explore (P2-T28) tasks **assume the relevant feat was negotiated**. But the **use-sites** for these feats — the `node.instances` op, the `sub` verb, and the `vp;explore` field — are all **P2 ops**, so P2 owns the use-time `unsupported` gate where a token sends one of these without having negotiated the implied feat. Each is tested in P2 at its own use-site, mirroring the same pattern: P2-T16 gates `node.instances` on `feat=instance` (`instances_without_feat_unsupported`); P2-T22 gates `sub ev=<pointer>` on `feat=pick`/`event` (`sub_pick_without_feat_unsupported`); P2-T28/P2-T1 gate `vp;explore` on `feat=explore` (`explore_without_feat_unsupported`). Per G7's implication rules `pick⇒event` and `explore⇒event`, the implied base feat (`event`) is also required; the emitted `detail=` names the requested feat (`pick`/`explore`). The handshake **negotiation** itself remains P1's; P2 only exercises the use-time rejection at the verbs it introduces.

## P2-T1 — `vp` control-frame ingress + multi-viewport store (apc_end back-channel change)

**Deliverable.** In `toastty-graphics/src/tgp/decoder.rs` add the `vp` verb decoder `decode_vp_frame(header, body) -> Result<VpFrame, TgpError>` where `VpFrame` is `enum { Upsert(VpOp), Destroy(ViewportId) }`. The **upsert** form (no `op=` key, or `op=upsert`) produces `VpOp { id: ViewportId, anchor: Anchor, cells: CellRect, camera: Option<NodeId>, root: Option<NodeId>, z: i32, clear: Option<Rgba>, render: RenderOpts, explore: Option<ExploreOpts>, screen_affinity: ScreenAffinity, clip_to_scroll_region: bool }` (sparse-merge over an existing viewport, same absent/null/value three-way as `node.upsert`, §6.1). The `explore` field is the first-class viewport controller field §10.1 (s10 line 17) defines on the `vp` frame; `Viewport.explore` carries the same type. `decode_vp_frame` parses the `explore` sub-map by **delegating to P2-T28's `ExploreOpts` decoder** (P2-T28 extends `apply_tgp_vp` to route the decoded sub-map through the `feat=explore` use-time gate before the controller is stored — see P2-T28); the field itself is defined here so the struct P2-T1 owns has a decode home for it. **Nullable vs non-nullable `vp` fields (three-way merge, §6.1).** Nullable (CBOR null clears to default): `camera` → `None` (implicit default camera, §10.5), `root` → `None` (whole scene), `clear` → `None` (transparent), `explore` → `None` (CBOR null clears/tears down the controller; absent → preserve the existing controller; value → set/replace, subject to the P2-T28 feat gate). Non-nullable (CBOR null is rejected with `tgp;x;code=null_not_allowed;detail=<field>`, viewport unchanged, no partial apply): the `vp` id itself, and — on an **initial create** (no prior viewport for that id) — `anchor` and `cells` (a viewport cannot exist without an anchor and a cell rect). `z`, `screen_affinity`, `clip_to_scroll_region`, and `render` are non-nullable scalars/sub-maps (absent → preserve; value → set; null → `null_not_allowed`). The **explicit-destroy** form is a `vp` frame carrying `op=remove` (text header) addressing an existing `vp=<id>`; it decodes to `VpFrame::Destroy(id)` and removes that viewport via the shared teardown path (P2-T36) with `DestroyReason::Explicit`. `op=remove` for an unknown `vp` id is a no-op (no `tgp;x` — idempotent teardown). This `op=remove` discriminant is the explicit-destroy wire form the design's §10.7 implicit-only list did not enumerate; it is introduced here so an app can deterministically tear down a pinned viewport (which is otherwise never cell-evicted). In `toastty-graphics/src/tgp/scene.rs` extend `Scene.viewports: Map<ViewportId, Viewport>` (P1 created the single-viewport struct) to hold many, keyed in the **per-token** namespace (§8.4, G1). **`ViewportId` is a composite key `{ token: Tok, raw: u16 }`** (G1 id hardening / §8.4): the wire `vp=` carries only the raw `u16`, but the store key qualifies it with the creating token so the same raw `vp=1` may exist concurrently under AP1 and AP2 as two distinct map entries and namespace isolation holds. The test helper is token-aware: `vid(tok, n)` builds `{tok, n}`, and the single-token convenience `vid(n)` binds to the test's active handshake token (most tests use one token, so `vid(1) ⇒ {AP1, 1}`); multi-token tests use the qualified form. In `toastty-term/src/tgp/mod.rs` extend the apc_end back-channel: where P1's `apc_end` returned unit / a single scene op, it now returns a decoded `TgpFrame` enum that includes `TgpFrame::Vp(VpFrame)`, and `Term` applies it via `Term::apply_tgp_vp` (routing `Upsert`/`Destroy`), resolving the wire `vp=<raw>` against the frame's `tok=` to form the composite `ViewportId`. **This is the called-out cross-crate `apc_end` change**: the parser's `apc_end` signature gains a return value carrying the decoded frame so `Term` can route `vp`/`sub` frames (vp/sub are control frames, never binary-read — §7.2). Add `&self` accessor `Term::tgp_viewports() -> &Map<ViewportId, Viewport>` and `Term::tgp_viewport(id: &ViewportId) -> Option<&Viewport>`.

**Design refs.** §10.1, §10.5, §6.1 (three-way sparse merge + `null_not_allowed`); G1 + **G11** (private per-token id map: cross-token addressing is unrepresentable, raw-id collisions coexist as distinct composite keys, `denied` is RESERVED with no ingress trigger — supersedes the base-spine G1 "denied on cross-token" prose), G4 (vp frames correlate by `vp` id, no `txn`), G2 + **G11(c)** (late-bound camera/root never reject; a cross-token camera/root ref late-binds to default, never `denied`; no existence oracle per G11(b)), G3 (`null_not_allowed`).

**Depends on.** P1 (tgp scene model + single Viewport struct), P1 (framer/CBOR decode), P1 (`Term::tgp_scene()` accessor + `pty_replies`). Note: the `vp;op=remove` **decode** (producing `VpFrame::Destroy`) lands here; the **apply** routing that calls the shared `destroy_viewport` helper is completed when P2-T36 lands (no build cycle — the decoder is independent, and the `vp_op_remove_*` tests run once T36's helper is wired).

## P2-T2 — Inline anchor: Unicode-placeholder-cell binding (cells authoritative, F3)

**Deliverable.** In `toastty-term/src/tgp/inline.rs` (new) add the placeholder-cell binder: on `anchor=inline {line,col}` creation the terminal lays kitty-style Unicode placeholder glyphs into the grid for the requested `cols × rows` and records the **live placeholder-cell set** `Viewport.placeholder_cells: BitGrid` / `Vec<CellAddr>` on the viewport. **Concrete placeholder encoding:** each bound cell stores the Unicode placeholder codepoint `U+10EEEE` (the kitty Unicode-placeholder sentinel) as its glyph and carries the owning `ViewportId` in the cell's metadata field (reuse the P1 cell-metadata slot that today holds image-placement ids). A cell is a TGP placeholder iff its glyph is `U+10EEEE` AND its metadata holds a `ViewportId`; any other glyph written into that position is an overwrite (P2-T11). The stored `Anchor::Inline { line, col }` is an **initial hint only**; `Viewport::live_cell_rect(&self, grid) -> Option<CellRect>` is derived from the current landed placeholder cells, never re-reading the hint. Add `Term::tgp_viewport_live_rect(id) -> Option<CellRect>` and the per-cell accessor `Term::tgp_cell_placeholder(addr: CellAddr) -> Option<ViewportId>` (returns the owning viewport id iff the cell is a live TGP placeholder) so detach/re-emit/bind tests assert against a concrete seam. Wire the placeholder glyph emit through the existing `Perform` write path.

**Named grid-mutation test seam (resolves the "move helper" gap).** The cell-relocation precondition used by `inline_hint_not_reread` (P2-T2) and the reflow/scroll tests (P2-T9/T10) is driven through one concrete, deterministic seam, not an unnamed helper: `Term::test_scroll_grid(lines: i32)` (a `#[cfg(test)]` Term method that scrolls the grid — and the placeholder cells it carries — by `lines` rows exactly as a text scroll would, the same primitive the real scroll path uses) for plain relocation, and the real CSI/Perform byte sequences for the wrap/region cases: a resize→rewrap is driven by the existing terminal resize entry point `Term::set_grid_size(cols, rows)` (the SIGWINCH/resize path), and a DECSTBM scroll by feeding `ESC[<top>;<bot>r` (set region) followed by the scroll-inducing line feeds. P2-T9/T10 reference these by name so the "move/scroll/rewrap the cells" precondition is as concrete as the ingress byte sequences elsewhere.

## P2-T5 — Per-viewport pixel cap: max_viewport_px_w / _h rejection

**Deliverable.** In `toastty-graphics/src/tgp/layout.rs` (validation entry called from `Term::apply_tgp_vp`) reject any viewport whose **on-screen clamped** pixel size still exceeds the per-viewport pixel cap with `tgp;x;code=cap_exceeded;detail=max_viewport_px` to the owning token; the viewport is not created or updated. Applies to both inline and pinned. Together with the P2-T3 on-screen clamp this is the oversized-VRAM backstop (§15.1).

**Cap-key resolution (spine vs §10.3 drift).** The spine's G7 cap list names this `max_viewport_px` (singular family name); §10.3 uses the split `max_viewport_px_w` / `max_viewport_px_h`. A width/height cap genuinely needs two numbers, so **P1's caps table advertises the split pair `max_viewport_px_w` and `max_viewport_px_h`** (the two concrete keys P2-T5 reads), and the spine's singular `max_viewport_px` is the **scope-prefix/family name** under which that pair lives (and the `detail=max_viewport_px` advisory spelling, harmless per G3 since `detail=` is non-load-bearing). P2-T5 therefore reads `max_viewport_px_w`/`_h` from P1's table and emits `detail=max_viewport_px`. This pins the cross-doc key so P2-T5 never reads a key P1 does not expose.

**Design refs.** §10.3 (per-viewport pixel cap); G3 (`cap_exceeded`), G7 (cap list; `max_viewport_px` family name → split `_w`/`_h` keys).

**Depends on.** P2-T3, P1 (caps).

## P2-T7 — Depth-aware compositing against the constant-depth text plane

## P2-T34 — Back-channel ordering, coalescing & backpressure

**Deliverable.** In `toastty-term/src/tgp/backchannel.rs` (new) make all terminal→app traffic — `tgp;e` events, `tgp;a` acks, `tgp;x` errors, and DA1 — share **one ordered FIFO** (never reorders; advertised ordered so apps correlate `txn` acks). **Coalescing:** consecutive still-pending events of the same `(viewport, ev-type)` where `ev ∈ {hover, drag, camera, wheel}` may coalesce to the latest before flush; `click`, `dblclick`, `down`, `up`, `enter`, `leave`, `resize`, `destroyed`, and **all** acks/errors/DA1 are **never** coalesced and **never** reordered. **Backpressure:** if the channel exceeds advertised `max_backchannel_bytes`, drop the **oldest coalescable** entries first (hover/drag/camera/wheel); never drop or delay an ack, error, or non-coalescable event. Token scoping is orthogonal (each token's reports tagged; order within a token's stream is FIFO). **Scope note (enqueue order is P1's, FIFO preservation is P2's):** the *enqueue order* of the handshake `tgp;r` and DA1 (`tgp;r` before `ESC[c`) is established by P1's handshake/DA1 path; this task only guarantees the FIFO **preserves** that enqueue order (does not reorder) — it does not set it. The `da1_after_tgp_r_ordering` test therefore asserts order-preservation through this channel, not that P2 chooses the order; a P1 enqueue-order regression is out of this task's scope. Add `Term::tgp_backchannel_snapshot() -> Vec<BackchannelFrame>`.

**Design refs.** §12.5.4 (back-channel ordering & coalescing, backpressure); G4 (ordered FIFO), G1 (token tagging orthogonal).

**Depends on.** P2-T23, P1 (`pty_replies` / DA1 ordering).

**Tests.**

## P2-T38 — RIS full teardown across tokens; DECSTR soft-reset leaves scene intact (G10)

**Deliverable.** In `toastty-term/src/tgp/mod.rs` wire the RIS (`ESC c`) and DECSTR (`ESC [ ! p`) reset paths for TGP state. **RIS** is the guaranteed VRAM-recovery path (§10.7, G10): it tears down the **entire** TGP scene of **every** token — assets, materials, nodes, **viewports (inline and pinned)**, all offscreen color+depth targets, all pick targets/buffers, all subscriptions, all explore controllers, and any pending chunk buffers — frees all GPU buffers, and **invalidates all session tokens** (a subsequent frame must re-handshake). RIS destroys viewports via the shared `destroy_viewport` path but is silent (it does **not** emit per-viewport `tgp;e;ev=destroyed` — the tokens are being invalidated wholesale; no live sub survives to receive it). **DECSTR** (soft reset) leaves the TGP scene fully intact — no viewport, target, sub, or token teardown — locking the §10.7 hard-vs-soft contrast. This is the load-bearing counterpart to P2-T13 ("2J keeps pinned; RIS destroys everything"). **Post-RIS frame behavior under an invalidated token (pins the load-bearing consequence of invalidation, G10).** After RIS invalidates all session tokens, a subsequent frame bearing a now-invalid token **does not address or mutate any state**: it is **rejected with `tgp;x;code=bad_token`** to that token. Per **G11(d)**, `bad_token` is the code for "a frame that needs a session token but lacks a *valid* handshake"; an invalidated token is exactly such a frame. This is distinct from the G5/G11(d) silent-drop case (a writer that *simply never handshaked* is dropped silently): a token that **was** handshaked and is now invalidated is a **recognizable** error condition, so the terminal emits `bad_token` rather than silently dropping. (Synonym `token_denied→bad_token`, G3; NOT `denied` — `denied` is RESERVED under G11(a) and would never apply here.) This makes the `bad_token` closed-enum member reachable from P2's RIS path. The app must re-handshake (`tgp;q`→`tgp;r`) to obtain a fresh valid token before any further `vp`/`sub`/`p` frame takes effect. Add `Term::tgp_token_valid(tok) -> bool`.

**Design refs.** §10.7 (RIS full teardown across tokens, DECSTR leaves scene untouched); G10 (RIS = full scene teardown all tokens; DECSTR intact), G3 + **G11(d)** (`bad_token` = a token-requiring frame lacking a valid handshake — reachable from a post-RIS invalidated-token frame; distinct from the silent-drop of a never-handshaked writer; `denied` RESERVED per G11(a)), G5 (handshake = error-reporting opt-in / silent-drop for never-handshaked).

**Depends on.** P2-T1 (viewport store), P2-T6 (offscreen targets), P2-T20 (pick targets), P2-T21 (subs), P2-T28/T30 (explore/controller state), P2-T36 (shared teardown).
